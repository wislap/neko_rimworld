# 从下载安装到第一次咨询

第一次接触 N.E.K.O 也没关系。这里会说明每个下载项的用途、安装位置，以及如何连接你的殖民地。当前是独立的“教程”页；设置、连接检查和已保存的回答请到“面板”中操作。已经完成的步骤可以跳过。

## 1. 先准备这些

需要分别安装两个部分：Bridge Mod 装进 RimWorld，配套插件装进 N.E.K.O。两者一起工作，才能在对话中读取当前殖民地。

- RimWorld 1.6 和 Harmony：前者是游戏本体，后者是 Mod 所需的公共依赖。Steam 用户订阅 Harmony 后等待下载完成；非 Steam 版本请按 Harmony 作者的手动安装说明操作。

- N.E.K.O 本体：用于对话和管理插件的桌面伙伴。请装在运行 RimWorld 的同一台电脑上。

- Bridge Mod + N.E.K.O RimWorld 插件：普通咨询只读；显式开启自动游玩后，插件可提交受保护的配置修改。请选用配套版本，本教程对应 Mod v3.3.0。

- 一个模型服务：需要服务地址、模型名称，以及服务商要求的 API key。RimWorld 咨询模型与 N.E.K.O 角色模型分别配置。

- [下载 N.E.K.O 本体](https://github.com/Project-N-E-K-O/N.E.K.O/releases)

- [N.E.K.O 官方安装说明](https://github.com/Project-N-E-K-O/N.E.K.O#readme)

- [在 Steam 创意工坊获取 Harmony](https://steamcommunity.com/sharedfiles/filedetails/?id=2009463077)

- [下载 Bridge Mod v3.3.0（.zip）](https://github.com/wislap/NekoRimWorld/releases)

- [Mod 发布说明与校验文件](https://github.com/wislap/NekoRimWorld/releases)

- [前往插件发布页获取 .neko-plugin](https://github.com/wislap/n.e.k.o_plugin_neko_rimworld/releases)

- [插件源码仓库](https://github.com/wislap/n.e.k.o_plugin_neko_rimworld)

请在发布页查找配套 Mod v3.3.0 ZIP；未列出附件时，该包尚未发布。插件请在发布页的 Assets（附件）中寻找 .neko-plugin 文件；如果还没有这个附件，说明插件安装包尚未发布，可以等待发布，或参考下方的源码构建说明。GitHub 自动生成的 Source code ZIP 不是可直接导入的插件包。

首次安装 N.E.K.O，请在官方发布页选择适合自己系统的下载项。Windows 用户先完整解压，再运行其中的 N.E.K.O.exe。按本体引导完成首次设置和对话模型配置，确认能正常聊天后，再安装本插件。其他系统或源码安装请参考上方官方说明。

本教程按同一台电脑上的桌面安装讲解。连接地址 127.0.0.1 只代表本机，远程电脑和容器网络不适用这套直接连接步骤。玩家无需安装 bench 或 .NET SDK。默认咨询只读取信息并提供建议；在面板中显式开启自动游玩后，才会允许受保护的原生操作。

## 2. 安装游戏 Mod

1. 退出 RimWorld，使用上面的链接下载 NekoRimWorld-3.3.0.zip。请选择这个明确命名的 Mod 安装包，不要选 Source code。

2. Steam 用户在库中右键 RimWorld，选择“管理 → 浏览本地文件”找到游戏安装目录；其他版本请打开自己的游戏安装目录。

3. 解压 ZIP，把得到的 NekoRimWorld 文件夹放进游戏目录下的 Mods 文件夹；如果没有 Mods，可以新建。不要只把 ZIP 文件放进去。

4. 核对下面的安装路径。About 应直接位于 NekoRimWorld 内；如果出现两层 NekoRimWorld，说明多套了一层文件夹。

5. 启动 RimWorld，在 Mod 列表中启用 Harmony 和 N.E.K.O RimWorld Bridge。将 Harmony 放在 Core 和依赖它的 Mod 前面，按提示重启游戏。

```text
RimWorld/Mods/NekoRimWorld/About/About.xml
```

安装完成后，应能在游戏的 Mod 设置中找到 N.E.K.O RimWorld Bridge。ZIP 已包含编译好的游戏 DLL 和运行依赖，无需自行编译。

如果是更新旧版，请先退出游戏，把旧 Mod 文件夹移到游戏目录外备份，再放入新版本。只保留一份启用的 Bridge，并核对插件与 Mod 版本是否配套。

## 3. 安装 N.E.K.O 插件

在插件发布页的 Assets 中下载 .neko-plugin 文件。保留这个文件即可，不需要手动解压，插件中心会负责安装。如果你已在安装好的插件详情中看到本教程，可以继续下一步配对。

1. 从 N.E.K.O 主界面打开“插件中心”。这里是本体的插件管理页面，不是 RimWorld 的 Mod 列表。

2. 选择“导入”，选中下载的 .neko-plugin 文件，核对包信息后按页面提示完成安装。

3. 在插件列表中找到 N.E.K.O RimWorld，进入详情后点击“启动”。安装完成不等于已经启动，本插件默认不自动启动。

4. 插件详情中的“教程”用于阅读本指南，“面板”用于实际操作。面板有“最近建议”“历史记录”“自动游玩”“调试”“设置”五个页面。

需要时可以随时回到“教程”查阅步骤。如果本体没有“导入”入口，或无法显示面板，请检查本体版本，按官方说明更新。导入成功只说明插件已安装，游戏连接和模型服务仍需分别确认。

### 可选：从源码构建插件安装包

这条路径适合熟悉 Git、uv 和终端的用户。普通玩家可以等待 .neko-plugin 发布。请先安装 Git、uv，并满足 N.E.K.O 官方源码运行要求；桌面安装包目录不等于源码仓库。

准备一份支持插件 CLI 和 Hosted 面板的独立 N.E.K.O 源码。全新下载可以使用下面的命令，之后保持终端位于得到的 N.E.K.O 文件夹内：

```text
git clone https://github.com/Project-N-E-K-O/N.E.K.O.git
cd N.E.K.O
```

将插件克隆到 plugin/plugins/neko_rimworld，安装依赖后构建。第一条命令要求目标文件夹尚不存在；已有源码请按自己的更新流程操作，并在构建前核对源码版本与 Mod 发布说明。

```text
git clone https://github.com/wislap/n.e.k.o_plugin_neko_rimworld.git plugin/plugins/neko_rimworld
uv sync
uv run neko-plugin sync neko_rimworld --clean
uv run neko-plugin build neko_rimworld -o neko_rimworld.neko-plugin
```

构建后，当前 N.E.K.O 源码目录会出现 neko_rimworld.neko-plugin。按上面的第 3 步，把它导入你实际使用的 N.E.K.O。构建不会自动安装或启动插件，未发布源码的构建也不代表正式版验收已经完成。

## 4. 配对并连接殖民地

端口用来确定本机连接位置，配对码用来确认连接的是你的插件。游戏与插件两端必须一致，默认端口为 48919。

1. 保持 N.E.K.O 和 RimWorld 插件运行。在 RimWorld 中打开“选项 → Mod 设置 → N.E.K.O RimWorld Bridge”。

2. 点击“生成新配对码”，勾选“启用 N.E.K.O 连接”，复制“配对码”并记下“连接端口”。

3. 关闭游戏设置窗口以保存并应用。插件尚未填写相同信息时，游戏显示“正在连接”是正常的。

4. 切换到“面板 → 设置 → 游戏连接”，填写相同端口并粘贴配对码，点击“保存并应用连接设置”。

5. 等待显示“设置已保存并应用”，然后载入想咨询的殖民地并保持游戏运行。暂停游戏也能咨询，只停留在主菜单则没有当前殖民地。

6. 切换到“面板 → 调试 → 咨询测试”，在“游戏连接检查”卡片中点击“读取殖民地概况”。这只读取游戏信息，不调用模型，也不会发起咨询。

确认顶部显示“游戏已连接”和当前殖民地，概况对应刚载入的存档。游戏连接成功还不代表模型可用，下一步再配置模型。

保存后配对码输入框会保持空白，这是正常的；留空表示保留已保存的配对码。只有在游戏中重新生成了配对码，才需要同步更新插件，不必每次游玩都重新生成。

## 5. 配置咨询模型

RimWorld 咨询使用独立模型，与角色聊天模型、N.E.K.O 的猫爪／Agent 配置分别设置。请从服务商获取地址、准确的模型 ID 和 API key；API key 是模型服务凭据，不是游戏配对码。

1. 切换到“面板 → 设置 → 模型服务”，填写服务商提供的 OpenAI 兼容基础地址，通常以 /v1 结尾，例如 https://your-provider.example/v1。不要填写完整的 /chat/completions 接口地址。

2. 填写该服务实际提供的模型名称。需要支持流式 Chat Completions 和工具调用的模型，服务商显示的宣传名称不一定就是模型 ID。

3. 按服务商要求填写 API key。远程服务请使用 HTTPS；明文 HTTP 只适合本机服务，例如 http://127.0.0.1:8000/v1，不允许把密钥发往远程的明文 HTTP 地址。

4. 首次使用通常保留高级设置默认值即可。点击“保存模型设置”，等待保存结果后再开始提问。

咨询会把你的问题和相关游戏信息发送给这个服务，可能产生费用。打开教程、保存设置、检查游戏连接和浏览已保存历史，都不会调用咨询模型。

“已配置”只表示已填写并保存，不等于服务通过了实际请求测试；能否响应会在第一次咨询时确认。已保存的密钥不会再次显示，输入框留空会保留原值。

保存结果“尚未确认”时，先核对同一次保存的状态，不要连续重试。插件重启后，先检查当前地址、模型、端口和凭据是否已配置，再决定是否重新保存。切换面板页面会保留输入草稿，完整关闭或重载面板会丢弃未保存输入。

## 6. 开始第一次咨询

1. 回到 N.E.K.O 主界面，进入你想使用的角色对话，打开猫爪面板（爪子图标，也称 Agent／NekoClaw）。

2. 打开猫爪／Agent 总开关和“用户插件”开关。如果本体提示配置 Agent 模型或插件服务尚未就绪，请先按本体提示完成。只配好 RimWorld 独立模型，还不会自动启用本体的工具调用。

3. 确认 RimWorld 插件仍处于启动状态，游戏已载入想咨询的殖民地。使用本插件不需要额外打开键鼠控制或浏览器控制。

4. 发送一个明确提及 RimWorld、希望读取当前游戏的问题，例如：

> 请用 RimWorld 插件查看我当前的殖民地，现在最该先处理什么？为什么？

咨询开始后，面板会显示进度。等待时可以继续游戏或切换面板页面；停止或重载插件会中断咨询。完成后先看角色回复，再到“最近建议”展开保留的完整回答。

如果对话没有发起咨询，先核对上面的两个开关。“调试 → 咨询测试”可以直接测试插件，其中“运行咨询”会实际调用模型，可能产生费用，和不调用模型的游戏连接检查不同。

## 7. 阅读和保存回答

“最近建议”展示当前殖民地最近一次已保存的讨论。点击“查看完整回答”展开全文，也可以复制完整回答；阅读旧回答不会再次调用模型。

“历史记录”支持按已保存的问题和对话角色查找，也可只看当前殖民地。阅读旧结果时请留意所属殖民地和时间，游戏未连接时也能浏览已保存的历史。

想继续讨论，请回到同一角色的对话，提及原问题或相关人物。已保存的回答反映读取时的情况，不会随着游戏进程自动更新。

文件导出失败不一定代表回答丢失。先查看或复制已保留的正文，再决定是否重新咨询。分享截图或日志前，请遮去 API key、配对码和其他私人信息。

下次使用时，启动 N.E.K.O 和本插件，沿用已保存配置，再载入殖民地即可。需要时可在插件中心开启自启。更新前请先停止插件、备份配置与历史，再导入配套的新安装包。

### 当前源码中的 v3.4：工程、生产与生活

以下说明对应正在开发的源码能力，需要配套重建的插件与游戏 Mod。上文仍保留已命名发布包的安装步骤；本节没有宣告 v3.4 安装包已经发布，也没有宣告这些新增能力已经完成实机、模型服务或普通安装包验证。更新插件源码不会自动替换游戏 DLL。

继续使用原来的角色对话提出需求，不需要另开控制台或建筑审批页面。可以先只讨论：

> 请查看基地东侧的实际地形和障碍，给我一个小房子的候选方案：卧室、吃饭的位置和通畅的入口。先说明材料缺口和你还不能确认的地方。

候选会与正式采用的方案分开展示。在“面板 → 自动游玩”中可以阅读“工程”“生产与生活”“观察覆盖”和“决策历史”；关闭自动游玩时，这些记录仍可阅读。要允许持续执行，请先在同一页面检查目标与约束，再点击“开启自动游玩”，并在对话中说明希望推进哪个工程。开启模式不会自动采用此前的旧候选，也不会要求逐件家具点击批准。

**房屋如何落地。** 模型基于当前游戏加载的定义、真实格点和原生放置检查提出方案，记录正式采用的修订，再通过已有受保护的原生操作提交。单个方案的总占地最多为 **62×62 格**，外围还会保留一圈观察格，整体原生采样最多 **64×64 格**。当前支持范围内的蓝图、地板、屋顶和区域操作仍由游戏中的普通工作完成；殖民者需要材料、通路、技能和工作时间，不会直接生成成品房屋。

工程页分别显示“放置已记录”“建筑已完工”和“用途评价”。放好蓝图之后，还要等待原生施工和后续观察；用途尚未评价时会明确显示。任意 Mod 家具、特殊施工流程以及所有房间类型的效果仍需具体核对。玩家取消、替换或接管的元素会保留停止意图；找不到旧对象时，需要重新核对，不会仅据缺失就当作重建授权。修改方案或接管要求仍在原对话中提出。

**资源如何分配。** 可以说“先满足住宅，厨房推迟；说明木材的联合缺口和分配后还缺多少”。例如库存为 80、住宅需 60、厨房需 50，单独看两项都够，联合需求却缺 30。“生产与生活”分别展示独立需求、联合需求和正式选择的份额，保留选择时采样、地图和来源。地面物资、己方持有、其他对象持有与商人物资分别列出；数量本身不证明所有权、可接触性或可用性。分配表达规划意图，不会锁住游戏库存。库存或需求变化后，规划者要重新评价。

**生产和伙食如何表达。** 继续通过对话要求调整已支持的生产订单与生活配置，例如“优先稳定做饭，再安排非紧急加工；先核对工作台、配方与原料”。新增伙食能力读取、管理原生食物方针及分配；编辑共享内容会影响正在使用同一方针的人。若只想影响指定人员，可以明确说“只调整 A 和 B，其他人当前规则保持原样”；若希望共同方针及其后续使用者一起变化，需要明确说明动态共享范围。页面显示选择时的影响评价、额外成员和接管保护，实际应用时还会核对真实成员。

接管要求也要说清范围：“由我负责 A 的方针分配”保护方针引用；“由我负责 A 实际生效的伙食规则”还涉及共享内容对 A 的影响。现有授权、接管与归还路径继续生效，没有新增产品审批环节。共享方针评价和所需原料充足，也不会直接证明殖民者最终按计划生产或进食。

**观察覆盖如何看。** 规划者可以登记当前支持的建筑、生产、食物方针条件，并选定对象、采样间隔、到期和次数上限。“观察覆盖”会区分等待注册、持续覆盖、部分覆盖、未覆盖及待处理条件，列出原生回执。提出观察要求本身还没有建立覆盖；过期、达到次数上限或失去连接后，需要重新核对。换档和重连也要重新绑定。旧事实会标为历史证据，不能据此认为新读档仍在持续观察。这里没有对整张地图的一切事件自动监控。

### 建筑图像、附件与视觉输入

工程图是由原生格点与方案叠加生成的 SVG 预览，会标出未观察格、冲突、范围、采样区间和来源哈希。这是一张派生示意图，不是游戏相机截图。面板中的归档图像引用会显示 PNG 的尺寸、字节哈希和来源；保存了图片不表示模型已经看到了它。

已有报告导出通道在报告含图像附件时导出 ZIP，内含 `report.json`、`report.md`、`manifest.json` 和 `media/` 下的原始 PNG；没有图片时仍按 Markdown 导出。SVG 当前用于面板预览，没有单独的 SVG 下载按钮。文件交付由本体处理，应以实际导出回执为准；失败时可先阅读或复制已保留的正文。

视觉输入默认关闭。实际模型端点将由使用者另外选定，本指南不预设某个服务已经支持图片。确认端点支持图片后，在“面板 → 设置 → 模型服务 → 高级：运行与模型用量上限”中：

1. 打开“启用视觉输入”。
2. 将“每图预约输入 token”设为大于 0、至多 1,000,000 的整数，再点击“保存模型设置”。默认关闭时预约值为 0。
3. 核对同一次保存的回执，再进行需要看图的实际咨询。预约用于控制输入预算，不是服务商账单，也不会自动证明端点接受了图片。

关闭视觉输入后仍可本地预览和导出已保存图像。是否实际向模型发送图片，要看真实模型请求记录；不能仅凭生成了图、保存了附件、打开了开关或回答里一句“已看图”判断。软件与固定状态界面检查覆盖了这些路径，实机施工、模型选择和真实端点行为需要依据实际运行结果。

## 8. 遇到问题时

按实际遇到的情况查看。展开这些说明不会自动测试、修改设置或调用模型。

### 找不到 Mod 或插件

找不到 Mod 时，核对第 2 步的 About/About.xml 路径，并确认 Harmony 已下载。找不到插件时，请在 N.E.K.O 中导入 .neko-plugin，不要放到 RimWorld 目录。没有面板时，检查插件是否已启动及本体版本。

### 一直连接中，或配对失败

确认游戏已勾选“启用 N.E.K.O 连接”，并已关闭设置窗口应用。核对插件在同一电脑上启动，两端端口和配对码完全一致。游戏重新生成配对码后，也要在插件中保存。若提示端口被占用，请在两端改为同一个空闲端口并应用。

### 已连接，但没有当前殖民地

请载入存档，等待会话出现，再读取一次殖民地概况。主菜单下的连接不代表已载入殖民地。换档后刷新面板，核对殖民地再提问。出现不兼容提示时，按发布说明核对已安装 Mod 和插件版本。

### 模型已配置，但咨询失败

先读失败提示，再核对基础地址、模型 ID、密钥权限和服务余额，并确认支持流式 Chat Completions 与工具调用。游戏连接检查无法验证模型。服务过载或超时时可以稍后再试，每次新咨询都可能产生费用。

### 角色只聊天，没有调用 RimWorld

核对当前角色的猫爪／Agent 总开关和“用户插件”，再确认插件已启动。明确说“请用 RimWorld 插件查看当前殖民地”。直接咨询测试成功、对话仍未调用时，请检查本体 Agent 设置；直接测试成功不代表对话调用链路已验证。

### 保存结果尚未确认

先点击“核对这次保存状态”，查看同一次操作结果和当前配置。密码框空白不代表密钥或配对码被清空。插件重启可能丢失旧回执，因此再次保存前应先检查已生效配置。

### 回答未完成，或无法下载文件

先读回答旁的说明。咨询未完成、历史保存未确认和文件导出失败是不同情况。可以先复制已保留正文，需要时再打开这次回答的高级诊断，不必仅为下载文件而重复付费咨询。

需要反馈时，请提供 N.E.K.O、插件和 Mod 的版本、卡在哪一步，以及页面上的错误提示。请遮去 API key、配对码和其他私人信息，不要把凭据贴到 Issue 中。
